## 2) القاعدة الحية (cgwn) — ما هو موجود
| الجانب | الحالة |
|---|---|
| البيانات | شركتان (نشطة/مؤرشفة)، عميلان، موقع واحد، جهاز واحد (بموقع، فترة 90 يومًا)، زيارة واحدة بلا موقع، أمر عمل واحد بلا موقع، لا سجلات صيانة ولا مرفقات |
| الإيقاف | `company_has_perm`/`company_member_row` تشترط `companies.status='active'` ⇒ الإيقاف يمنع الوصول فعليًا مع بقاء البيانات ✓ |
| التعديل | `platform_update_company` يعدّل 4 حقول فقط (الاسم، السجل، الهاتف، المدينة) |
| الحذف | مسموح فقط لشركة مؤرشفة **بلا أي عضوية** ⇒ عمليًا لا تُحذف أي شركة انضم مديرها؛ لا معاينة لما يرتبط بها |
| الإسناد | `technician_customers` (فني↔عميل، `is_primary` غير مستخدم)، الإلغاء **حذف** بلا تاريخ، لا إسناد على مستوى الموقع |
| الجدولة | `devices.maintenance_interval_days/last/next_maintenance_at`؛ حساب بالأيام (+90) لا بالأشهر؛ لا تاريخ بداية جدول؛ لا حالة استحقاق |
| الإشعارات | `run_maintenance_alerts` تُستدعى **فقط عند فتح لوحة التحكم** (`dashboard/page.tsx`)؛ لا مهمة خلفية؛ `pg_cron` متاح غير مثبت؛ منع التكرار موجود بـ `dedupe_key` ✓ |
| نقل الجهاز | تغيير `site_id` من نموذج التعديل مباشرة بلا سجل نقل |
| الزيارة | `visits` + `maintenance_records` (تاريخي غير قابل للتعديل ✓) بلا نوع زيارة، بلا قراءات، بلا صور خاصة بالزيارة (المرفقات عامة `attachments`) |
| البلاغات | لا جدول بلاغات/أعطال؛ أوامر العمل `corrective/emergency` موجودة |

## 3) خطة التنفيذ المقترحة (كل مرحلة: ترحيل آمن + واجهة + اختبارات)
- **م0 (بلا قاعدة):** إعادة نشر الإنتاج بعد موافقتك؛ رسالة خطأ إعداد واضحة بدل 500.
- **م1 الشركات:** توسيع التعديل لكل حقول الشركة مع تحقق؛ معاينة ارتباطات قبل الحذف؛ الإبقاء على «إيقاف» و«أرشفة» كبديل؛ حذف نهائي فقط لشركة بلا بيانات تشغيلية مع تأكيد بالرقم.
- **م2 المكان والنقل:** جدول `device_transfers` (من/إلى موقع، السبب، المنفّذ، التاريخ) ودالة `device_move` (نقل بين عملاء = صلاحية مستقلة)؛ منع تغيير الموقع من نموذج التعديل؛ مسار معالجة الأجهزة بلا موقع؛ عرض أجهزة العميل مجمعة حسب الموقع؛ منع أرشفة موقع له أجهزة نشطة.
- **م3 الإسناد:** إضافة `site_id` اختياري وتواريخ `started_at/ended_at` إلى الإسناد (إنهاء بدل حذف)، فني أساسي واحد لكل عميل، تحديث `is_assigned_customer` ليحترم النطاق؛ لوحة الفني `/my-work`.
- **م4 الجدولة والإشعارات:** `schedule_start_date`، فترة بالأشهر (1/2/3/… افتراضي 3) مع حساب نهاية الشهر، `due_status` محسوبة، تطبيق افتراضي على مجموعة أجهزة دون تغيير القائم إلا بقرار؛ تثبيت `pg_cron` ومهمة يومية لـ `run_all_maintenance_alerts` (مسبق 7 أيام قابل للضبط، عند الحلول، تأخر، تصعيد إداري).
- **م5 الزيارة والسجل والبلاغات:** `visit_type`، `visit_devices` (الأجهزة المفحوصة فعليًا وقراءاتها ونتيجتها)، صور الزيارة قبل/بعد بمسار `{company}/visit/{visit}/`، تصحيح موثق للسجلات المعتمدة، جدول `device_faults` (بلاغ ← أمر عمل ← إصلاح ← إعادة فحص) دون المساس بمواعيد بقية الأجهزة.
- **م6 التقارير:** الاستحقاقات، الأعطال المفتوحة، سجل النقل، أداء الفنيين بالأعمال المكتملة فقط، بنطاق صلاحية كل مستخدم.

كل ترحيل: نقطة استعادة ← تجربة جافة متراجع عنها ← موافقتك ← تطبيق ← `db:cgwn:verify*`.
